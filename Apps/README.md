# Apps/ — buildable reference apps (Phase 2, Track A)

The four Phase 1 source fixtures (`Fixtures/apps/*`) stay as they are; they remain the input of
the static audit and the MOCK resolver. This folder contains the same four apps as **Xcode
projects that build and run on an iOS 27 simulator**, so AppIntentsTesting can measure them.
All data is the synthetic catalog of `dataset/v1.2/entities` (generated into `*/Shared/SeedData.swift`).

```bash
Apps/tools/generate_all.sh          # regenerate SeedData.swift and the four .xcodeproj (deterministic)
scripts/real_run.sh messages_ok     # build + run the AppIntentsTesting harness + ingest (see README)
```

Projects are generated by `tools/make_xcodeproj.py` (stdlib Python; no XcodeGen/Tuist). They use
file-system-synchronized groups, carry no `DEVELOPMENT_TEAM`, and build for the simulator with
"Sign to Run Locally". Running on a physical device needs a development team (see
`docs/spotcheck-protocol.md`).

## Fixture ↔ app correspondence

| Phase 1 source fixture | Buildable app | Bundle ID | Same declarations | Differences (and why) |
|---|---|---|---|---|
| `messages_ok` | `Messages/OK` (MessagesOK) | `dev.siriready.messages.ok` | `.messages.sendMessage` + `.messages.draftMessage` + `.messages.setMessageReadStatus`; `OpenConversationIntent` via App Shortcuts; `ContactEntity` / `ConversationEntity` / `MessageEntity` are `IndexedEntity` and indexed with `indexAppEntities`; View Annotations on all four screens; disambiguation of same-name / same-reading contacts | Parameter names and required properties follow the iOS 27.1 App Schemas (`destination`, `content`, `message`, `isRead`, union types `MessageDestination`, `ReadReaction`, required enums) because the AppIntents metadata processor rejects anything else |
| `messages_broken` | `Messages/Broken` | `dev.siriready.messages.broken` | (a) no `draftMessage` companion — Xcode itself warns: *App Intents use case 'Message Sending' is missing the schema 'messages.draftMessage'*; (b) `ContactEntity` is **not** `IndexedEntity` and is not indexed; (c) `MessageDetailView` has no View Annotation | (b) The pure Phase 1 form (no index **and** no string query) does not build: Xcode 27.1 stops with the halting metadata error *"AppSchemaIntent 'SendMessageIntent' requires UnionValue case 'ContactEntity' to conform to 'IndexedEntity', 'UniqueAppEntity', 'TransientAppEntity', provide a default 'EntityStringQuery', or provide an 'IntentValueQuery'"*. The app therefore keeps a name-only `EntityStringQuery` (the nearest buildable form). |
| `calendar_ok` | `Calendar/OK` (CalendarOK) | `dev.siriready.calendar.ok` | `.calendar.createEvent` / `.updateEvent` / `.deleteEvent`, `EventEntity` / `CalendarEntity` indexed; `OpenEventIntent` and `ShareEventIntent` via App Shortcuts; `ShareEventIntent` is `cloud_allowed` and posts to `invites.orbit.example`; disambiguation of same-title / same-reading events | Schema parameter names (`event`, `entity`, `span`, `startDate` …) and union types `EventAlarm` / `EventLocation` |
| `calendar_broken` | `Calendar/Broken` | `dev.siriready.calendar.broken` | (a) no disambiguation (first event with that title wins); (b) Share only in SiriKit (`INIntent` subclass + `INExtension` handler, not an App Intent); (c) `on_device_only` `CreateEventIntent` calls `geo.orbit.example` when a location is given | (b) The SiriKit classes are hand-written instead of generated from an `.intentdefinition`, so there is no `.intentdefinition` file (the Phase 1 fixture has one, which adds a medium C5 finding there). |

The Phase 1 audit gives every app the same check IDs as its fixture
(`Tests/SiriReadyTests/RealRunTests.swift`, `testAppsAuditMatchesFixtures`).

## Layout

```
Common/BenchSupport.swift   EgressRecorder (intercepts every URLSession request locally and records the host),
                            BenchLog (persisted side effects), DebugProbeIntent (DEBUG-only, isDiscoverable = false)
Messages/Shared, Calendar/Shared   seed data, schema enums/unions, stores (shared by OK and Broken)
<Domain>/<Variant>/App      the App Intents surface that differs between variants (+ siriready.yaml next to it)
Harness/                    UI-testing target shared by the four projects (never imports app code)
tools/                      make_seed.py, make_xcodeproj.py, generate_all.sh
```

## Bench instrumentation and its effect on measurements

- Nothing leaves the machine: `EgressRecorder` answers every HTTP(S) request locally with `{}` and records the host.
  F8 is "an `on_device_only` intent *attempted* to reach a host".
- Launch arguments `-siriready-screen <name> -siriready-ids a,b,c` put the root view into a dataset screen state
  so `viewAnnotations()` can be measured.
- `DebugProbeIntent` returns the effects / egress log and is excluded from discovery; the static audit does not
  scan `Common/` or `Shared/`.
